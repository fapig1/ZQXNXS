## 1. 硬约束

1. **触发阈值统一**：四色均在100%开心值触发专属动作，不设不同触发线；差异化只落在加分、回落、重新武装、冷却、时长五个常量上。
2. **冻结模型红线**：26骨骼，手臂/手指权重牵拉肚皮，非根骨骼平移超1~2mm有FBX回读问题。全部动作用头部/躯干/肩肘小幅旋转实现，**文中幅度一律为建议上限口径**，实作以FBX回读不破肚皮为准，宁小勿大；表情走2D贴图/面片，增强走粒子/billboard，不新增三维道具与布料。
3. **配置化**：每色常量进入配置（形象ID→行为ID→触发条件→参数组），共用同一套判定代码，不在代码里写死任何一色的数值；这些 ID 与参数已作为 `PetConfig.VariantTunings` 与 `AnimatorStates` 进入 `PetBehaviorConfig.asset`（2026-10-27）。
4. **机制一致性硬性检查**：每色必须满足 **回落值 ≤ 重新武装阈值**。满值挂起期间不衰减（design_v1 §6.2），若回落值高于重新武装阈值，该宠将永远无法重新武装。下表已按此校验。

## 2. 每色专属动作演出（候选A已选定）

> 2026-09-22 用户决定：四色均采用候选A作为动画指导；以下备选仅保留记录，不制作。四段专属动作幅度仍为建议上限口径，逐段FBX回读验证；共享大笑幅度已单独放宽，见 §2.5。

### 2.1 classic 暖黄「得意」— `classic_proud` 得意三连晃（沿用 + 改良）

- **编排**：挺胸抬头亮肚皮（起手）→ 身体左右各晃一次、回中（高潮，即“三连晃”）→ 单手拍胸/叉腰定住（收势）。
- **幅度上限**：躯干后仰8°、头后仰10~15°、左右摇摆各8~10°（约0.4s/次）、收势单肩外展30~40°。
- **表情与增强**：开心眯弧眼 + 上扬微笑弧贴图；头顶2~3颗星点粒子。
- **素材证据**：classic.png（挺胸仰头望币）、mf-pose-belly.png（叉腰挺胸）、milkyfrog-hero.png（端立收势）。
- **备选（不制作，保留记录）**：`classic_wave` 献宝挥手（单肩外展45°上限，mf-pose-wave 压半幅度）；`拍肚得意笑`（naiwalaugh_t4 前倾拍肚扩为小动作）。

### 2.2 calm 湖蓝「佛系」— `calm_zen` 佛系点头（沿用 + 改良）

- **编排**：双手交叠搭腹、缓缓闭眼（起手）→ 缓慢点头三次、幅度递减（高潮）→ 头回正、睁眼、嘴角微扬（收势）。
- **幅度上限**：点头 +5°~−8° 且递减（8°→6°→4°），躯干随动2~3°；**手臂全程保持搭腹静态不动**（规避牵拉风险的关键设计）。
- **表情与增强**：闭眼细弧 → 舒展微笑弧贴图；淡蓝涟漪/放射光环粒子缓慢旋转。
- **素材证据**：naiwa-standing.png（搭腹手位）、calm.png（闭眼+光环）、naiwalaugh_t1（同组合站姿）。
- **备选（不制作，保留记录）**：`calm_gaze` 背手远望（纯头部水平转15~20°上限望远→回正；全素材中风险最低，可作保底）。

### 2.3 rage 朱红「兴奋怒吼」— `rage_roar`（沿用 + 改良）

- **编排**：前倾蓄力、怒眉圆睁（起手）→ 头后仰张嘴怒吼 + 双臂向侧上张开 + 全身高频小抖（高潮）→ 整体一沉回正（收势）。
- **幅度上限**：前倾5~8°、头后仰10~15°、双肩外展30~45°、躯干高频抖动±2~3°@8~10Hz；收势下沉用Root Y下移0.01~0.02m上限或膝微屈，不抬腿跺脚。
- **表情与增强**：横椭圆怒吼嘴贴图——**嘴角拉开保持水平或略下扣、绝不上扬**（大笑与怒吼的唯一形态分界），暗红褐口腔 + 上排小白牙 + 可选圆舌；怒眉 + 圆睁直视眼（不得画成开心眯弧）；短火花粒子 + 地面冲击环billboard。语义是“兴奋到极致”，不表示开心值变负。
- **素材证据**：meme_rage.jpg（张臂喝止+怒眉直视）、rage.png（张嘴白牙+前倾）、mf-pose-wave.png（张臂幅度参考）。
- **备选（不制作，保留记录）**：`rage_halt` 喝止一顿（单臂抬至肩侧掌向前→0.5s定帧急停；多宠同屏嫌吵时的降级版）。

### 2.4 divine 紫「神格觉醒」— `divine_awaken`（沿用 + 改良）

- **编排**：低头敛目静止（起手）→ 极缓抬头 + 双眼渐变为纯白发光 + 双臂向两侧缓展 + 光环光柱渐显（高潮）→ 定住庄严站姿后归位（收势）。
- **幅度上限**：低头5~8°→抬头后仰10°（用时≥0.6s，庄严感=慢）、双肩外展30~40°掌心渐转向前、躯干挺胸3~5°。
- **表情与增强**：垂眼→纯白无瞳发光眼贴图渐变（四色中唯一换眼型的专属动作，白眼是其身份特征）；头顶椭圆光环粒子渐显旋转 + 紫金光柱/辉光billboard。
- **素材证据**：divine.png（祝福举掌+白眼+正面对称）、meme_divine.jpg（白光眼+辉光）、angel.jpg（摊掌+光环的可行组合）、milkyfrog-hero.png（端立）。
- **备选（不制作，保留记录）**：`divine_bless` 祝福一指（单手缓抬至胸前掌心向外定住+颔首一次；双臂展开破面时的单手保底）。

### 2.5 social_laugh 共同大笑（全部共用）

> 2026-09-28 已按下表思路制作为 2.4s 骨骼片段（第一波65°、捧腹前弯35°、第二波105°，保留拍肚段），实际节奏以[接入记录](../../Docs/共享大笑动作接入记录_20260928.md)为准；下表保留为设计依据。

- **节奏表**（2.2s两波式，依据 naiwalaugh_t1~t5 逐帧；与 design_v1 的 2.4s 相容，余量给收势静止）。**幅度按用户2026-09-22决定放宽：夸张角度越大越好，身体后弯至90°可接受**，不再采用灵感审查文档中“头后仰20°”的保守上限：

| 时刻(s) | 阶段 | 身体/头（上限口径） | 嘴/眼贴图 |
|---|---|---|---|
| 0.00–0.30 | 预备吸气 | 双手搭腹，身体微收2~3° | 闭眼细弧+小微笑 |
| 0.30–0.70 | 第一波爆发 | 躯干+头合计后弯40~60°，身体后靠 | 嘴峰值：横椭圆+上排白牙+暗口腔；开心眯弧 |
| 0.70–1.10 | 回弹 | 回落至后弯20~30° | 嘴保持大开 |
| 1.10–1.50 | 前倾拍肚 | 前倾5~8°，双手小幅交替拍肚（肘屈伸±10°） | 嘴大开，眯弧眼 |
| 1.50–1.90 | 第二波爆发 | 后弯至峰值70~90°（“笑弯了腰”，90°为用户允许上限） | 第二峰值，眯弧眼 |
| 1.90–2.20 | 收势 | 回正，手回腹前 | 渐闭为微笑弧，睁眼 |

- 多宠同屏：协调器统一开始后各宠**相位错开0.1~0.2s**、后弯峰值±3°随机化（配置项）；divine用白眼专用变体，其余三色开心眯弧。
- 站姿后弯90°（脊柱/髋部骨骼旋转，双脚不离地）按用户决定允许；它与“笑倒翻滚”（t6 的 Root 整体旋转+四肢大角度）不同，后者仍不做；双手捧头大笑仍不进v1。红线明细见灵感审查文档第四节。
- **验收前提**：后弯用脊柱/髋部旋转实现，不引入非根骨骼平移；每段必须过“冻结骨架加Action→检查→FBX回读”流程。若90°回读破面，如实报告，由用户在“降低幅度”与“按冻结说明归档并新开shape_revision处理权重”之间决定，不擅自改权重、不擅自降幅。

## 3. 四色阈值参数差异化（2026-10-27 用户定稿）

> 2026-10-27 用户定稿：§3 参数按本表采用，已进入 `PetBehaviorConfig.asset`。

统一100%触发、统一共用判定代码。0.7s 是 `Petted`（TouchReact）单次行为时长，执行期间不接受新点按且不排队；输入判定侧不再保留独立的 0.45s 冷却。下表常量逐色配置，定稿为起始值，可在 `PetBehaviorConfig.asset` 调整。

| 参数（定稿起始值） | classic 暖黄 | calm 湖蓝 | rage 朱红 | divine 紫 |
|---|---|---|---|---|
| 性格基调 | 得意·均衡基准 | 佛系·慢热持久 | 兴奋·快热高频 | 神格·隆重稀有 |
| 单击加分 | +6% | +4% | +8% | +6% |
| 双击加分 | +10% | +7% | +12% | +10% |
| 满值回落至 | 70% | 75% | 65% | 65% |
| 重新武装阈值（开心值≤） | 80% | 80% | 85% | 75% |
| 专属冷却（距上次开始） | 8s | 8s | 6s | 12s |
| 演出时长 | 2.0s | 2.5s | 2.0s | 2.5s |
| 触发节奏画像 | 与v1基准一致 | 攒得最慢，但演完后保留值最高 | 最容易再次攒满、最常演出 | 数值门槛+最长冷却，最稀有隆重 |

**差异化逻辑**：

- **classic** 全部取 design_v1 原建议值，作为调参基准锚点，其他三色相对它偏移。
- **calm** 加分最低（佛系难哄），但回落最少（75%，演完仍是高开心状态）——演出后的“余韵持久”补偿低加分。
- **rage** 加分最高、回落最深（65%）、重新武装阈值最宽（≤85%，回落即满足数值条件）、冷却最短（6s）——来得快去得快，最活跃；兴奋人设与高频演出一致。
- **divine** 回落65%且重新武装阈值收得最紧（≤75%，需再攒10%才重新武装）、冷却最长（12s）、演出最隆重——神格觉醒物以稀为贵。

## 4. 与 design_v1 §6.2 触发契约的一致性核对

| 契约条款 | 差异化后的处理 | 结论 |
|---|---|---|
| 触发＝合格交互把夹紧后内部值从小于1推到1 | 四色同一条判定，仅后续常量不同 | 不变 |
| 满值周期资格：可触发→待执行/执行中→已释放，一周期一次 | 状态机共用，常量进配置组 | 不变 |
| 演出开始时原子消费资格并释放至回落值 | 释放目标逐色（70/75/65/65%） | 仅常量变化 |
| 重新武装＝开心值≤阈值 且 距上次开始≥冷却 | 两条件逐色（阈值与冷却各四套）；**每色回落值≤重装阈值已校验** | 仅常量变化 |
| 8s内攒满只挂起一条满值请求，等待冷却与有效跟踪 | 冷却逐色（6/8/12s），挂起规则共用 | 不变 |
| 加载时待执行先显示“开心已满”，点按确认不加分；v1迁移Happiness=1同此 | 与色无关 | 不变 |
| 行为时钟为完成唯一权威，动画事件只做声音/表情提示 | 与色无关 | 不变 |
| `Petted` 单次行为 0.7s 期间不接受新点按（不排队）、点击不同奶蛙互不影响 | 与色无关，共用（输入侧无独立冷却） | 不变 |

## 5. 多宠协调影响

- SocialCoordinator 检查“参与者无未开始的满值高优先级请求、处于可让出状态”的判定不变；rage 的高频满值只是让该宠更常处于“请求挂起/演出中”，不影响判定逻辑本身。
- rage 冷却6s意味着它在双宠验证期最可能与靠近大笑争行为通道：候选保留2s、开始即记5s组冷却的既有规则已覆盖，双宠实测时优先观察 rage 参与配对的表现。
- social_laugh 相位错开0.1~0.2s 与 ±3° 随机化进组协调配置，不写死。
