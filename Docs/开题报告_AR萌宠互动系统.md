## 一、选题背景与意义

### 1.1 行业背景

增强现实经过多年发展，已从营销尝鲜进入日常应用阶段。移动端 AR 借助手机摄像头即可将虚拟内容叠加到真实环境，无需额外硬件；《泛 XR 产业发展白皮书（数字基础设施篇）》（2024）显示终端与内容生态持续扩张，轻量化、本地化的 AR 应用成为普及的主要形态。与此同时，"电子宠物"作为情感陪伴类数字产品拥有长期市场：拓麻歌子系列硬件累计销量约 9,810 万台（截至 2025，维基百科），放置类宠物《旅行青蛙》2018 年初在中国大陆两周内即获超 390 万下载。两者交叉的"AR 萌宠"——把虚拟宠物放进用户真实桌面——是移动 AR 中情感化、日常化的细分方向。

### 1.2 技术背景

- **跟踪技术的可得性**：Vuforia Engine 的图像目标识别为纯视觉方案，不依赖 Google ARCore 与 GMS 服务，可在国内主流安卓设备（含未预装 Google 服务的 iQOO 等品牌）上运行，为课设提供了可落地的跟踪路线。
- **表达门槛的下降**：Blender 等开源工具 + Unity 的 Animator/Generic 骨骼体系，使单人可在数周内完成低多边形萌宠的建模、绑定与动画闭环。
- **对照：单点"放到桌上"已不构成产品**。Google 搜索已支持通过 Scene Viewer 把 3D 动物直接放进现实桌面（系统级集成，国内不可用）。因此本课题的价值不在"把模型放到桌上"这一单点能力，而在**持续的行为关系**——宠物有状态、有习惯、可被照料的系统设计。

### 1.3 研究意义

1. **应用意义**：验证"桌面实体卡 + 行为状态驱动"的 AR 萌宠交互在普通安卓设备上的可行性，为轻量级情感化 AR 应用提供一种可复制的实现范式。
2. **方法意义**：将游戏 AI 中的行为状态机与 AR 跟踪事件结合，形成"跟踪层—交互层—行为层—表现层—数据层"的分层架构，业务规则可配置、可测试，对同类课设与原型开发具有参考价值。
3. **教学意义**：完整覆盖"识别—交互—动画—数据—真机验证"的移动应用开发链路，是一次综合性的工程实践。

### 2.2 现状小结与机会

1. **需求已被验证**：从拓麻歌子到 Pokémon GO，"照料虚拟生物"与"和它合影"是跨硬件、跨年代的稳定需求。
2. **供给出现空档**：品类标杆 Peridot 停运、轻量单机代表 AR Dragon 停更、国内《一起来捉妖》边缘化，而"无服务器、可长期离线拥有、单机可玩"的 AR 宠物在国内安卓设备上基本空白。
3. **技术前提成熟**：Vuforia 图像跟踪不依赖 GMS，覆盖国产主流机型；Unity 6 LTS + C# 生态完整，适合单人四周量级的工程。

## 三、研究目标与拟解决的问题

### 3.1 总体目标

在普通安卓设备上实现"**定位召唤—实体投喂—行为反馈—趣味互动—反应解锁—存档与拍照**"的完整体验闭环，验证图像跟踪与行为状态驱动机制在移动 AR 萌宠中的应用可行性。

### 3.2 拟解决的问题

1. **空间稳定性**：如何在手持移动设备上维持虚拟角色与实体标记之间可用的空间关系，并妥善处理跟踪丢失与恢复。
2. **交互确定性**：如何将"卡片靠近—停留—移开"的连续物理动作转化为**恰好一次**的有效交互，排除误触发与重复结算。
3. **行为可理解性**：如何让相同操作在不同宠物状态下产生合理、可理解的差异化反馈（饥饿时进食、饱腹时拒绝、困倦时迟钝），使玩家逐步学会"阅读"宠物。
4. **资产可行性**：如何在单人、数周、无外包条件下产出有表现力的角色资产，并保证移动端性能。
5. **工程完整性**：如何在课设周期内覆盖识别、交互、动画、存档、拍照、真机测试的完整链路，形成可安装、可演示、可复现的成果。

### 3.3 预期特色与创新点

1. **实体道具输入**：食物卡与宠物小窝卡的相对位置构成投喂交互，图像标记同时承担"产品道具"职能；该交互方式在手机 AR 萌宠中尚无直接竞品（见市场调研）。
2. **可解释的行为状态驱动**：不采用生成式 AI 等黑箱方案，而以可配置、可测试的行为状态机实现"宠物有性格"的感知，规则透明、行为可复现，符合课程设计的验证要求。
3. **单机轻量、数据归用户**：无服务器、无内购，本地带版本号 JSON 存档；对照 Peridot 停运案例，突出"宠物真正属于用户"的定位优势。
4. **面向国产中端设备的完整真机验证**：跟踪方案不依赖 GMS，以 iQOO Z9 Turbo（Android 15）为首要实测平台，给出如实的能力边界记录。

## 四、研究内容与系统设计方案

### 4.1 系统总体架构

系统采用五层架构，自上而下解耦：

~~~mermaid
flowchart TD
    A[摄像头与图像跟踪层<br/>Vuforia Image Targets] --> B[目标坐标与跟踪状态<br/>小窝局部坐标系 / 米制]
    B --> C[交互判定层<br/>投喂 / 逗弄 / 追球事件]
    D[触屏输入] --> C
    C --> E[行为状态机层<br/>饥饿·开心·困倦 × 行为优先级]
    F[ScriptableObject 配置<br/>食物·阈值·反应条件] --> E
    E --> G[表现层<br/>Animator 动画·表情·音效]
    E --> H[界面层<br/>uGUI 状态面板·反应图鉴]
    E <--> I[数据层<br/>版本化 JSON 本地存档]
    G --> J[AR 场景合成与拍照]
~~~

各层职责与约束：

- **跟踪层**只提供目标标识、位姿、有效性与更新时刻，不直接修改游戏数值；跟踪丢失时暂停一切新空间交互，不依据过期位姿继续计时。
- **交互层**将空间关系与触屏输入转化为一次性事件：投喂需双目标同时有效，结合平面距离、高度、停留时长、冷却与"离开后再次进入"判定；同一次有效进入只结算一次，跟踪恢复不自动生成新事件。
- **行为层**维护长期状态（饥饿、开心、精力）与执行中行为（进食、移动、休息）的分离，明确优先级与打断规则；结算通过动画事件或完成回调在确定时刻执行，避免 Update 与动画事件双重触发。
- **表现层**仅根据行为层指令播放动画、表情与特效，业务规则不写入动画脚本。
- **数据层**使用带版本号的本地 JSON 保存状态数值与解锁内容，不保存场景对象引用；缺失或异常存档回退到可用默认状态。

### 4.2 功能设计（基线功能）

| 编号 | 功能 | 设计要点 |
| --- | --- | --- |
| FR-01 | 小窝定位与召唤 | 单张已知尺寸小窝卡建立角色局部坐标系（约 20cm 角色设计基准） |
| FR-02 | 跟踪状态处理 | 识别中 / 有效 / 丢失 / 恢复四态提示；丢失时暂停新交互并引导重新对准 |
| FR-03 | 实体投喂 | 双卡跟踪 + 距离/高度/停留/冷却判定，一次性结算；饱腹时拒绝并反馈 |
| FR-04 | 触屏逗弄 | 点击或滑动角色可交互区域触发表情动作；界面输入不穿透到角色 |
| FR-05 | 简单追球 | 在小窝定义的虚拟平面内投放小球，角色在限定范围内移动靠近 |
| FR-06 | 状态与行为反馈 | 饥饿、开心、困倦状态与进食、移动、休息行为分离联动 |
| FR-07 | 反应解锁 | 少量基于状态组合的趣味反应，图鉴式展示 |
| FR-08 | 本地存档 | 版本化 JSON；重启恢复；异常存档可回退默认 |
| FR-09 | 拍照留念 | 保存现实背景 + 角色的合成截图；失败路径有明确反馈 |

明确不作为首版验收的扩展项：应用内视频导出、多角色多食物、手部追踪、真实遮挡、语音/大模型对话、联网与多人。追球平面由标记坐标定义，不代表扫描真实桌面；触屏逗弄如实标注为触屏输入。

### 4.3 角色资产方案

- **形象方向**：奶蛙风格圆润小生物——小头、巨腹、短四肢的金黄色形象，呆萌、慵懒；**为原创设计，仅借鉴该风格的比例与气质，不精确复刻任何现有 IP 形象**（产品暂名"桌上有龙"与角色物种解绑）。
- **制作依据**：已完成《奶蛙建模参考简报》，含分部位比例表（总高 20cm 换算）、实测色值（体色 #F5C24B、腹 #F6ECDB 等）、逐部位建模要点与参考图集。
- **制作顺序**：轮廓与基础材质 → 骨骼与权重 → 待机、进食两个动作 → FBX 导出 Unity 校验（尺寸/朝向/脚底根节点）→ 补充移动、开心、困倦等动作与二维表情。
- **风险备选**：若三维资产进度受阻，降级为透明序列帧二维角色置于 AR 场景；该备选降低资产成本，但不能解决跟踪兼容问题，若启用将同步修订文档中的效果边界。

## 六、可行性分析

1. **技术可行性**：Vuforia 图像目标为成熟商用方案，纯视觉路线规避 iQOO Z9 Turbo 不在 ARCore 官方列表的风险；奶蛙资产已有量化建模简报与参考图集，Blender→FBX→Unity 流程已确认可脚本化调用。剩余风险集中在双目标跟踪稳定性与真机兼容，已列为第一周优先验证项。
2. **经济可行性**：全部工具链（Unity 个人版、Vuforia 免费开发者配额、Blender）无采购成本；实体卡可自行打印。
3. **时间可行性**：单人约 4 周，采取"先验证风险、再堆功能"的排布——第一周即完成环境锁定与真机样例，资产与玩法迭代建立在其上；若资产受阻有二维降级方案，若跟踪不成立则优先排查环境而非推进玩法（详见进度安排）。
4. **需求与市场可行性**：据市场调研（2026-09），"照料虚拟生物 + 合影分享"需求被拓麻歌子、Pokémon GO、《旅行青蛙》等产品跨代验证；品类标杆停运后，"无服务器、可长期离线拥有"的单机轻量 AR 宠物在国产安卓设备上处于空档位置。本课题为课程设计原型，不承担商业运营目标，该空位支持选题的现实意义论证。

## 八、验证方法与预期验收标准

以下为初步目标（阈值在第一周样例后确认，结果必须来自真实测试记录）：

| 维度 | 方法 | 初步目标 |
| --- | --- | --- |
| 识别能力 | 固定卡面尺寸，记录光照/距离/角度，重复识别 20 次 | 常规条件 ≥18 次成功，记录耗时与失败条件 |
| 交互正确性 | 重复投喂、短暂经过、长停留、移开再进入 | 一次有效进入仅结算一次 |
| 跟踪丢失 | 遮挡/移出后重新对准 | 丢失即停止新交互，恢复后规则一致，记录恢复时间 |
| 行为一致性 | 不同状态下触发投喂/逗弄/追球 | 反馈符合预设规则，结算不重复 |
| 性能 | 目标机连续互动 ≥5 分钟 | 约 30 FPS 起步目标，记录帧率/内存/发热 |
| 存档 | 重启恢复 + 异常存档注入 | 解锁内容可恢复，异常不致不可进入 |
| 拍照 | 保存合成图像 | 图像完整可访问，失败有反馈 |
| 界面 | 不同屏幕比例检查 | 主要控件可见可点，无关键截断 |
| 体验 | 3~5 人同一组任务 | 探索性记录理解障碍与建议，不推导统计结论 |

编辑器与 Blender 预览不替代真机验证；结果区分"已实现 / 已测试 / 目标 / 待验证"。

## 九、风险分析与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| Unity 6/Vuforia 环境搭建或真机兼容受阻 | 第一周门槛无法达成 | 第一周全时投入；必要时评估 Unity 2022.3 LTS 与当前 Vuforia 的支持组合；准备备机 |
| 双目标跟踪不稳定 | 投喂玩法不可靠 | 特征清晰的卡面；先单目标验证；测量丢失/恢复表现后再引入双目标 |
| 三维资产超期 | 表现力不足 | 只先做两动作；二维序列帧备选；按剩余时间提升还原度 |
| 交互误触发/重复结算 | 玩法不可信 | 距离+高度+停留+冷却+再进入多重判定；业务规则单元验证 |
| 性能与发热 | 体验下降 | 控制模型/贴图规模、轻量材质，真机实测并如实记录 |
| 权限/后台恢复 | 用户路径断裂 | 摄像头权限拒绝提示、切后台重入恢复纳入测试用例 |
