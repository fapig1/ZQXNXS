> ⚠️ **关于"AR Foundation / ARCore"**：本项目**不使用**它们，也不建议你现在下载。
> 原因是 iQOO Z9 Turbo 未出现在 Google 的 ARCore 支持设备列表中，
> 无法把 ARCore 当作可用前提。Vuforia 走纯视觉跟踪，不依赖 ARCore/GMS。
> 所以你要装的"AR API"只有 Vuforia 一个。

**怎么装进工程：它是 UPM 包，不是往 `Assets/` 里丢文件（2026-09-15 补充）**

这一点对本工程特别关键，因为 `ZQXNXS.ARPet.AR.asmdef` 与 `ZQXNXS.ARPet.EditorTools.asmdef` 都用
`versionDefines` 检测包标识 `com.ptc.vuforia.engine` 来点亮 `VUFORIA_ENGINE` 宏。
**`versionDefines` 只对 Package Manager 里的包生效**——如果把 Vuforia 当成普通资源解压进
`Assets/Vuforia/`，工程里就不存在这个包标识，宏永远不亮，`VuforiaTrackingSource` 的真实实现会一直
处于条件编译关闭状态，菜单"检查工程设置"也会一直报"未检测到 Vuforia Engine"。

Vuforia 官方的包标识就是 `com.ptc.vuforia.engine`（与两个 asmdef 中写的一致，无需改动），分发形式为
**UPM 包（`.tgz` 压缩包）**，安装后应落在 `Packages/com.ptc.vuforia.engine/`。两条装法：

| 路线 | 做法 | 备注 |
| --- | --- | --- |
| A（官方常规） | 从 Developer Portal 下载 Unity 版 SDK（`.unitypackage`），导入后它把 `.tgz` 装成 UPM 包 | 需要登录账号；`developer.vuforia.com/downloads/sdk` 页面本次未能抓取（需登录），具体文件名以你看到的为准 |
| B（git URL） | Package Manager → ＋ → **Add package from git URL** → `git+https://git-packages.developer.vuforia.com/#<版本>` | 或直接写进 `Packages/manifest.json` 的 `dependencies` |

> 已知社区坑：Vuforia 内部脚本**硬编码期望包位于 `Packages/com.ptc.vuforia.engine`**，
> 不要把它装到工程外的路径再做引用。

**`17.14.37628.2`**，并已确认含 C++ 工具链（按 `Microsoft.VisualStudio.Component.VC.Tools.x86.x64`
查询能返回该实例）。Windows SDK 已装 **`10.0.26100.0`**。此前的空文件夹与缺失状态已不再成立。

（历史记录：此前 `C:\Program Files\Microsoft Visual Studio\2022` 只是个空文件夹、
`vswhere` 返回 `[]`、Windows SDK 下只有 `UnionMetadata`。这条曾使 Android IL2CPP 打包必然在
C++ 编译阶段失败，现已修复。）

另一件仍然成立的事实：微软已把 **Visual Studio 2022 从下载页折叠**，主推 VS 2026，所以从官网首页找不到 2022 入口了。
但 2022 仍在支持期内（生命周期到 2032），**直接下载链接仍然有效**（已实测 HTTP 200）。
下文保留这一段是因为将来在别的机器上重装时还会遇到同样的问题。

**版本选择：2022 不是必须的，Unity 要的是工具链而不是 IDE。**

Unity 官方要求的原文是"**Visual Studio 2019 with C++ Tools component or later**"加
**Windows SDK `10.0.19041.0` 或更新**；Unity 构建失败时自己弹出的错误框写的是
"**Visual Studio 2022 or newer** with C++ compilers and Windows SDK"。两条都指向"2022 或更新"，
所以 **VS 2026（18.x / MSVC v145）在字面上满足要求**。Unity 通过 `vswhere.exe` 探测，
规则是"取已安装的、具备全部必需组件的最新一个实例"。

> ⚠️ **比版本号更重要的一条：只装一个。**
> 已经确认的故障模式是同时装了 VS 2022 与 VS 2026 时，Unity 用其中一个编译、用另一个链接，
> 报出 `_CxxThrowException` 链接错误与 `limits.h` 缺失一类底层错误。
> Unity 官方说法是"取最新的那个"且侧载"理论上应该可以"，但社区已复现失败。
> 装一个即可，不要两个都装。
