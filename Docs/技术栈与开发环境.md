# 技术栈、开发环境与项目结构

> 核查日期：2026-09-08。依据：开题说明、AGENTS.md、课程材料文字版、现有资产参考简报及本机只读检查。
> 本文区分既定方案、实际安装状态与待验证事项；目录树中的规划不表示工程或资产已经生成。

## 1. 应用如何开发

**Android App 的主工程是 Unity 工程 `ARPet/`。** 摄像头画面、AR 跟踪、宠物互动、动画和界面都在这个工程中集成，由 Unity 的 Android 构建工具链输出 APK。

Blender 负责制作模型、骨骼与动画，通过 FBX 和贴图交给 Unity。Vuforia Engine 作为 Unity 中的 SDK，提供图像目标识别、位姿与跟踪状态。Android Studio 与 adb 负责设备日志、安卓问题排查；需要相册等原生能力时，再按实际需要接入小范围的 Android 插件。

当前基线可以由一个 Unity 主工程承担，无需另建一套完整的 Kotlin/Java 应用。应用在前台显示摄像头中的桌面与角色，首要测试设备是 iQOO Z9 Turbo / Android 15。

~~~mermaid
flowchart LR
    B[Blender 源模型与动画] -->|FBX 与贴图| U[Unity 主工程 ARPet]
    V[Vuforia 图像跟踪 SDK] --> U
    C[C# 逻辑、uGUI、Animator] --> U
    U -->|Android 构建工具链| A[Android APK]
    D[Android Studio 与 adb] -->|日志与调试| A
~~~

## 2. 技术栈与版本决策

2026-09-08 用户明确确认采用 **Unity 6 LTS**，忽略本机已有 Unity 安装。环境按新建 Unity 6 LTS 工程与配套 Android 工具链准备；具体 Unity 发行版与补丁版本按 Vuforia 官方支持情况选择。

| 职责 | 采用方案 | 当前决策状态 |
| --- | --- | --- |
| 应用与场景 | Unity 6 LTS | 用户已确认；核对 Vuforia 支持表选择具体发行版与补丁版本，经样例验证后锁定 |
| AR 跟踪 | Vuforia Engine Image Targets | 先小窝卡单目标，再验证小窝卡与食物卡两个目标；SDK 版本待与 Unity 一起锁定 |
| 宠物与交互逻辑 | C# 行为状态机 | 跟踪、交互判定、状态数值、执行中行为分层处理 |
| 三维资产 | Blender，导出 FBX 与贴图 | 本机 5.1.1 后台 bpy 调用已验证；以已确认的奶蛙站立主视觉建模，首轮制作待机与进食两个动作 |
| 动画播放 | Unity Animator + Generic 骨骼 | 身体动作与二维表情、特效配合；形状键按实际导入结果验证 |
| 界面 | uGUI | 宠物状态、提示、反应图鉴、拍照入口；考虑手机、平板比例与安全区域 |
| 参数与存档 | ScriptableObject + 带版本号的本地 JSON | 配置与存档分开，首版不依赖后端 |
| Android 构建 | Android Build Support + 配套 SDK、NDK、JDK | 计划使用 IL2CPP、ARM64；具体 API、工具版本按所选 Unity/Vuforia 要求设置 |
| C# 编辑器 | 建议使用现有 VS Code | C#/Unity 编辑、调试扩展尚需配置与验证 |
| 调试与性能 | Unity Profiler、Android Studio、adb | 真机运行后记录日志、帧率与交互表现 |

文件流转规则：

- 修改模型、骨骼和动作时，打开 `ArtSource/Characters/Pet01/pet01.blend`；Python/bpy 工具放 `Tools/Blender/`。
- 导出后，将 FBX 与运行所需贴图放入 `ARPet/Assets/_Project/Art/Characters/Pet01/` 对应子目录。Unity 不直接依赖本机 Blender 自动导入源文件；FBX 内动作在导入设置中划分，再由 `Animations/` 下的控制器驱动。
- `ArtSource/References/` 中的图片、视频与网页供制作参考；用户已确认奶蛙站立主视觉 `milkyfrog-hero.png` 为建模基准，目录使用稳定标识 `Pet01`。目前尚无 `.blend`、`.fbx` 或已完成的角色动画。
- 音效作为后续增强项评估：原始与剪辑音频及来源记录计划放在 `ArtSource/Audio/`，应用实际使用的短音效放在 `ARPet/Assets/_Project/Audio/`，由 Unity 事件触发。当前只完成参考视频音轨检测，尚未试听、剪辑或导入音频。
- 标记卡设计源图保存在 `ArtSource/Markers/`，实际打印版与有效图像尺寸记录放在 `Docs/Markers/`。Vuforia 数据库按所选 SDK 的导入规则保留，常见运行数据位置为 `Assets/StreamingAssets/`；第三方包保留其规定的结构。
- C#、界面、AR 集成和 Android 构建设置都维护在 `ARPet/`。确需 Android Studio 编辑的原生插件源码再按需求规划；`GradleExport/` 是 Unity 生成的输出，不能代替 Unity 主工程。
- 提交 Unity 源码时保留 `Assets` 的 `.meta`、`Packages` 和 `ProjectSettings`；排除 `Library`、`Temp`、`Logs`、`Obj`、`.gradle` 与可重建的 Gradle 导出目录。APK 作为交付产物单独保存。

## 5. Unity 中如何接入 AR

以下是实施顺序，尚未执行：

1. 对照官方支持表选定 Unity 与 Vuforia，安装 Android 模块，在 `ARPet/` 创建 Unity 工程并记录版本。
2. 安装该版本 Vuforia Engine，完成许可与开发密钥配置，导入一张有明确实际尺寸的小窝卡目标。
3. 在最小验证场景配置 Vuforia 摄像头与 Image Target，先用简单几何体显示跟踪结果，构建 APK 并在目标手机验证摄像头、识别与丢失恢复。
4. 加入第二张食物卡，配置最多两个同时跟踪目标。`Scripts/AR/` 只输出目标状态和位姿；`Scripts/Interaction/` 将食物位置换算到小窝局部坐标，处理距离、高度、停留、冷却和离开后再进入。
5. 验证一次进入只触发一次、丢失跟踪暂停交互、恢复不自动投喂，再接入 `Pet/`、Animator 和待机/进食资产，逐步补齐界面、存档、拍照与其他基线功能。

资产使用米制单位，约 20 厘米作为角色高度的起点。Blender 到 FBX 再到 Unity 的轴向要实际检查：Unity 中角色朝向约定为局部 `+Z`、上方为 `+Y`，不能直接把 Blender 的 `+Y` 当成 Unity 的前方。灯光、预览相机、地台不随角色导出。
