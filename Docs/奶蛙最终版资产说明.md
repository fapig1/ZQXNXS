## 2. 造型基准

最终形体依据用户于 2026-09-10 选定的 [expression_frames.jpg](AssetReview/20260908_naiwa/expression_frames.jpg)，
并以外部生成候选 `ArtSource/Characters/Pet01/Candidates/Meshy_AI_Golden_Guardian_0910135714_generate.glb`
的**轮廓比例**为对照进行了收窄躯干、收肩、双臂前搭腹部、大腿内收、抬高嘴眼位置的修订。

- 站姿主要对照帧：`video_frames/mfstream_t1.png`、`mfstream_t6.png`。
- 候选模型仅用于比例对照，保存在 `REFERENCE_MESHY_NOT_EXPORTED` 集合中且**未进入 FBX**（`proportion_reference`）。
- 腹部截面设计参数：高 0.091 m、宽 0.0956 m、厚 0.0946 m（`abdomen_design_profile`）。这些是重建网格前的设计值，**不是参考图的精确测量**。
- 色彩：金黄色身体、奶油色腹部色块、绿色眼睛、棕色指趾、短尾。
- 造型为原创设计，仅借鉴奶蛙风格的比例与气质，不精确复刻任何现有 IP 形象。

## 4. 两段动画与结算点

| 动作 | 帧区间（源文件，30 FPS） | 时长 | 循环 | 内容 |
| --- | --- | --- | --- | --- |
| Idle | 1～91 | 3.0 s | 是 | 轻微呼吸、身体摆动、眨眼、摆尾 |
| Eat | 1～97 | 3.2 s | 否 | 注视低头、三次咀嚼、吞咽、抬头恢复 |

Eat 的时间安排与接入含义：

| 相对动作起点 | 表现 | 接入含义 |
| --- | --- | --- |
| 0～0.18 s | 中性准备 | 业务层确认本次投喂已获得执行资格 |
| 0.18～0.82 s | 前倾、低头、眨眼 | 脚底固定，行为身份不变 |
| 约 0.95 / 1.45 / 1.95 s | 三次咀嚼 | 嘴部表演；**不逐口增加饱腹值** |
| **2.4 s** | **吞咽** | **唯一建议结算点 `Consume`** |
| 2.52～3.16 s | 抬头恢复 | 不再次结算 |
| 3.2 s | 回到中性站姿 | 可切回 Idle |

源 Action 标记为 `Bite01` / `Bite02` / `Bite03` / `Consume` / `Complete`，
它们是**设计元数据**，不会自动变成 Unity Animation Event，也不会自动结算数值。

> **纪律：一次投喂只结算一次。** 代码里由 `BehaviorStateMachine` 在行为时长处结算
> （`OnExitSettled`），事件本身由唯一事件 Id 去重。如果以后改用 Animation Event，
> 必须先把行为层的时长结算关掉，**两者只能留一个**。

### 4.1 补充动作（2026-09-17）

在冻结的形体与现有两段动画之上只新增 Action，网格与骨骼未改动。三段动作与代码里的行为一一对应：

| 动作 | 帧区间（30 FPS） | 时长 | 循环 | 对应行为 | 状态 |
| --- | --- | --- | --- | --- | --- |
| TouchReact | 1～22 | 0.7 s | 否 | `Petted`（触屏逗弄） | 检查全部通过 |
| DozeLoop | 1～121 | 4.0 s | 是 | `Resting`（困倦） | 检查全部通过 |
| WalkLoop | 1～31 | 1.0 s | 是 | `Chasing`（追逐） | 8 项检查中 7 项通过，**穿地 1 项未过** |

- 机器可读记录：`ArtSource/Characters/Pet01/validation_report_extra_actions.json`，共 26 项检查，
  25 通过 / 1 未过（`passed: false`）。
- 运行日志：`ArtSource/Characters/Pet01/Logs/20260917_extra_actions/`（`export.log`、`validate.log`）。
- 生成脚本：`Tools/Blender/build_pet01_extra_actions.py`，分 `--phase build` / `export` / `validate` 三步。
- 三段动作都无根位移（Root 骨骼矩阵逐帧误差 0.0），起止姿态一致（最大 2.0 × 10⁻⁹ m）。
- FBX 回读：三个文件均为 1 网格 / 1 套 26 骨骼 / take 名正确，采样姿态与源文件的最大表面差异为
  TouchReact 8.0 × 10⁻⁸ m、DozeLoop 7.8 × 10⁻⁸ m、WalkLoop 4.2 × 10⁻⁷ m。
- **WalkLoop 未过的一项是 `WalkLoop_above_ground`**：判据为全程最低点 `> -0.0005 m`，实测
  -0.00079 m（超出判据 0.29 mm）。脚本对 WalkLoop 有意跳过 `planted_feet` 检查——行走时脚本来就该离地。
- 2026-09-17 晚已复核并**推翻**了"放大旋转会破坏 FBX 回读"的旧结论：隔离重跑 22° / 38° / -16°
  的回读是 5.8 × 10⁻⁷ m（干净）、穿地 -0.00059 m，但换来了 `smooth_motion` 不过（0.0109 > 0.010）。
  真实约束是**穿地与逐帧平滑度互相拉扯**，不是旋转幅度。穿地点也定位清楚了：只有 4 帧、全部在
  摆动腿刚开始抬起时、全是踝关节正下方那几个脚掌顶点，踝在那几帧比静止位置低约 0.6 mm。
  完整数据与下一步方向见首轮说明第 9.3、9.4 节。
- 三段动作在 Unity 里**尚未接入**：`PetConfig.Aspect.HasAnimatorClip` 仍把 `Petted` / `Resting` /
  `Chasing` 显式返回 `false`，动画做完了状态机也不会切过去。接线顺序见 `ARPet/README.md`。

## 5. 最终版的 Unity 导入步骤

以下是把冻结资产接入 Unity 的完整步骤。`ARPet/Assets/_Project/Scripts/Editor/ProjectSetup.cs`
里的菜单"桌上有龙 / 1. 生成默认配置与场景"已经能自动完成第 3 步与配置资产创建，
其余步骤需要人工确认。

1. **确认工程版本已锁定**，再打开 `ARPet/`。版本选择见[环境缺失与下载清单](环境缺失与下载清单.md)。
2. 让 Unity 完成首次导入并生成 `.meta`；**之后保留并提交这些 `.meta`**。
3. 执行菜单 **桌上有龙 / 1. 生成默认配置与场景**。该工具会：
   - 把 `Pet01.fbx` 的 Rig 设为 **Generic**、关闭材质导入、关闭动画压缩与 `Optimize Game Objects`；
   - 创建 `Assets/_Project/Configs/PetBehaviorConfig.asset`；
   - 生成 `01_TrackingSmoke.unity`（用模拟跟踪源）与 `02_Main.unity`（预留 Vuforia 挂点）。
4. **核对尺寸与朝向**：把角色放在 1 m 参考物旁，确认约 0.2 m 高、局部 +Y 向上、+Z 朝前。
   本轮只做过 Blender 的 FBX 回读，**尚未在 Unity 中确认坐标转换**，不能仅凭导出轴设置就宣称朝向正确。
5. **动作切片**：`Pet01_Idle.fbx` / `Pet01_Eat.fbx` 同样设为 Generic，可从主模型复制 Avatar。
   场景中只放一只主模型，取两个文件里的 `AnimationClip` 使用，**不要额外实例化两只角色**。
6. **裁剪与循环**：显示名设为 `Idle` / `Eat`，核对 3.0 s / 3.2 s 时长；
   `Idle` 勾选 Loop Time，`Eat` **不勾**。首轮检查阶段保持关闭动画压缩。
   FBX 回读时 take 名显示为 `Pet01Rig|Idle`、`Pet01Rig|Eat`，帧范围 2～92 / 2～98 是回读器起点偏移，
   时长与姿态一致；结算时刻请用**相对 clip 起点的秒数**，不要照抄源文件帧号。
7. **重建材质**（FBX 里不带材质）：
   `Pet01_Skin` 用同一张 sRGB 贴图、白色颜色乘数、Metallic = 0、Smoothness 起始 0.43；
   `Pet01_Eyes` 0.64；`Pet01_Oral` 0.57。Blender 的灯光与色彩管理不会随 FBX 变成 Unity 画面。
8. **Animator**：默认 `Idle`，`Apply Root Motion` **关闭**；Idle→Eat 过渡初值 0.12～0.20 s，
   Eat 播完回 Idle。先验证完整动作与过渡，再接一次性投喂与跟踪暂停规则。
9. **补充动作（4.1 节）**：`Pet01_TouchReact.fbx` / `Pet01_DozeLoop.fbx` / `Pet01_WalkLoop.fbx`
   同样设为 Generic、可从主模型复制 Avatar。`TouchReact` 不勾 Loop Time；`DozeLoop` 与 `WalkLoop`
   勾上。`WalkLoop` 尚未通过穿地检查，接入前先处理。

## 7. 解冻流程（如需修改形体）

形体冻结的目的是让后续的 Unity 与真机工作有一个稳定基准。如果确实需要改：

1. 先另存当前版本：`ArtSource/Characters/Pet01/Archive/<日期>_before_<修订名>/`，
   并把 `.blend`、贴图、预览、FBX、脚本与 `backup_manifest.json` 一起归档
   （沿用 `Tools/Blender/backup_pet01_meshy_revision.py` 的做法）。
2. 修改 `build_pet01.py` 或直接编辑 `.blend` 副本；**不要**在已冻结的文件上直接改。
3. 重新运行 `validate_pet01.py --roundtrip`，32 项检查全部通过才算完成。
4. 更新 `asset_manifest.json` 的 `shape_revision`、`source_sha256`、几何数值与日期。
5. 重新导出三份 FBX 与贴图到 `ARPet/Assets/_Project/Art/Characters/Pet01/`，
   更新本文第 1 节的哈希表与 `final_manifest.json`。
6. 在本文顶部加一行修订记录，说明改了什么、为什么改。

## 8. 复现命令

工具位于 `Tools/Blender/`，在项目根目录运行。
**注意：`build` 阶段会重新生成 `pet01.blend`，冻结版本已有内容，运行前务必先归档。**

```powershell
# 仅重新检查与导出（不改形体，安全）
& D:/blender.exe --background --factory-startup --python-exit-code 1 --python Tools/Blender/validate_pet01.py -- --roundtrip

# 完整重建（会覆盖 pet01.blend，冻结后不要直接运行）
& D:/blender.exe --background --factory-startup --python-exit-code 1 --python Tools/Blender/build_pet01.py -- --phase build
& D:/blender.exe --background --factory-startup --python-exit-code 1 --python Tools/Blender/build_pet01.py -- --phase export
python Tools/Blender/make_pet01_review.py

# 补充动作（4.1 节；只新增 Action 与 FBX，不改网格与骨骼）
& D:/blender.exe --background --factory-startup --python-exit-code 1 --python Tools/Blender/build_pet01_extra_actions.py -- --phase build
& D:/blender.exe --background --factory-startup --python-exit-code 1 --python Tools/Blender/build_pet01_extra_actions.py -- --phase export
& D:/blender.exe --background --factory-startup --python-exit-code 1 --python Tools/Blender/build_pet01_extra_actions.py -- --phase validate
```

`--phase build` 在动作已存在时会直接报错，加 `--force` 才覆盖重建；脚本以 `--force` 重建会连带重写
`pet01.blend`，运行前先确认归档完好。
