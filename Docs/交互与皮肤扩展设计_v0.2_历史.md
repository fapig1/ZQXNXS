# 交互与皮肤扩展设计

> **历史版本，已于2026-09-21退役。** 当前范围见 [交互与皮肤扩展设计](交互与皮肤扩展设计.md) v0.3。下文单宠换肤、食物卡、旧配色、先完成进食等不是现役要求。

> 版本：v0.2（2026-09-18 修订）
> 修订说明：纠正 v0.1 对方向的误解。四种肤色不是纯换色 + 通用表情分档，而是**"肤色即性格"**：每种肤色的奶蛙有自己的专属状态与专属动作，专属卡面以专属动作为画面主题，四张卡因此天然互不相同。按用户指示，**具体动作设计暂缓**，本文只锁定框架、数据结构与硬约束。
> 定位：基线交付（双卡投喂、逗弄、追球、状态行为、存档、拍照）之上的第一轮扩展设计。所有条目均不解除奶蛙最终版资产冻结：网格、骨骼、已有动画不改。

## 二、E1 肤色即性格

### 2.1 概念

- 4 套肤色：默认色 + 3 个变体（如红色系、嫩绿、粉、暖黄，色样以参考图风格定稿）。
- 每种肤色对应一种性格设定，拥有**一个专属动作**，由该肤色自己的状态阈值条件触发。用户给出的示例：红色系在开心度满值（100 开心）时进入"暴怒"演出——仅为示例，**各肤色的动作内容与触发条件均待设计**，开始制作前需先出"动作与阈值定稿表"。
- 专属动作是卡面的画面主题（见第三节）与玩法的收集点（见 2.3），一套设计两处复用。

### 2.2 材质实现方式

- 复用 2026-09-17 接入的三个 Standard 材质（Pet01_Skin / Oral / Eyes，Metallic=0）。肤色以 Skin 材质的贴图变体实现（同一 UV，改色相与色块布局），命名 `Pet01_Skin_<Variant>.png`；Oral 与 Eyes 原则上不动，保证表情素材跨肤色通用。
- 推荐贴图变体而非纯 `material.color` 染色：腹色、斑点、腮红等细节靠整体染色会一起变色。

### 2.3 数据结构与解锁

- 皮肤选择接入已有本地存档（版本化 JSON）：解锁条件绑定 `PetState.PetCount` / `PhotoCount` 等既有计数，不新增系统；默认肤色开局即用。
- 皮肤以稳定字符串 ID 记录（如 `classic` / `crimson` / `mint` / `sakura`），不存材质引用。
- **专属动作必须数据化**：`皮肤 ID → 专属行为 ID → 触发条件（PetNeed + 阈值）` 全部写入 `PetBehaviorConfig`，不在代码里按肤色硬编码。新增肤色不改逻辑代码。
- 专属动作按冻结骨架加 Action 的既有流程制作（2026-09-17 `TouchReact` / `DozeLoop` 同款），逐段过检查与 FBX 回读验证后经 `PetConfig.Aspect.HasAnimatorClip` 接入。

### 2.4 预算提醒

4 个专属动作 = 4 段新动画，是本轮扩展中最贵的项，排在最后做；每段动画定稿前先过"动作与阈值定稿表"评审。

## 三、E2 专属卡面

### 3.1 核心思路（用户方案）

**卡面可以是全彩的**：Vuforia 导入目标图后内部转灰度再提取特征点，颜色对跟踪既无帮助也无损害，现占位卡为灰度只是测试图偷懒，不是引擎要求；正式卡按彩色卡面美术做，仅受下述"灰度下仍需可分辨"约束。

专属卡面直接画该肤色奶蛙的**专属动作演出瞬间**。四张卡因动作姿态、表情、构图互不相同而天然可区分——这同时解决了 Vuforia Image Target 的灰度特征区分问题：不同姿态产生完全不同的明暗结构，优于"同版式只换配色"的方案。

彩色卡面的设计纪律（颜色引擎看不见，明暗结构才是它看见的）：

1. 主体与背景要有**明暗差**而不只是色相差（浅色奶蛙适合压暗底色或加粗轮廓线）；设计稿先去色自检，仍能分清蛙与背景才算过关。
2. 避免大面积无细节纯色块（特征点荒漠）；动作姿态、名称文字、边框花纹天然补足。
3. 打印用哑光纸、不覆亮膜，避免反光破坏对比度。
4. 工作流：定稿前先把**去色版**上传 Target Manager 看星级（星级即对灰度版评定），≥3 星再打彩色样卡做真机交叉验证，避免"彩色好看、灰度糊团"的返工。

卡面原画建议同时作为该专属动画的 pose 参考，一份设计两处使用；绘制卡面时可顺手定下动作的关键帧构图。

### 3.2 仍保留的验证要求

姿态差异解决"大方向区分"，但定稿仍需走硬验证：

1. 每张卡导入 Target Manager 后星级 ≥3。
2. **交叉干扰评分**：把 A 卡加为 B 卡所在数据库的干扰目标，确认各卡仍被正确识别区分，四卡两两通过。
3. 卡面含专属名称文字（文字是高质量特征点），四卡名称互不相同。
4. 打印后用真实光照实测识别距离与角度，记录到测试档案。

### 3.3 目标体系

- 卡面定稿前占位卡维持现状（`den_card_placeholder` / `food_card_placeholder` 已真机验证通过，不提前删除）。
- 皮肤卡逐张替换"小窝卡"：每种肤色一个 Image Target（尺寸 0.1 m 起步，按实际打印尺寸校准）；食物卡单独定稿一张。
- 运行期同一时刻只需跟踪一张皮肤卡 + 食物卡，`MaxSimultaneousImageTargets` 维持 2；数据集目标增多后，需真机回归"持错卡/多卡同框"的表现并如实记录。
- 印刷与拍照流程、纸张外框不当作有效目标尺寸的原则不变。

## 四、E3 阈值反应逻辑

反应分两层，均只读 `PetState` 快照（`Happiness` 0=低落→1=高兴，`Hunger` 0=饱→1=饿），阈值写入 `PetBehaviorConfig`：

- **通用层**：所有肤色共享的点击反应。基础复用已有 `TouchReact`（0.7 s）；分档规则待专属动作定稿后一并设计，避免两套阈值打架。
- **专属层**：当前肤色的专属动作按其触发条件触发，**优先级高于通用反应**；饥饿状态（`Hunger ≥ HungryThreshold`）时点击优先触发讨食短演出，与状态机"打断规则、行为优先级、唯一结算点"的既有约束一致。

### 4.1 结算规则（继承既有约束）

1. 同一次点击只结算一次演出；演出期间再次点击按冷却处理（冷却值入配置）。
2. 跟踪丢失时暂停反应判定，不根据过期位置结算。
3. 新反应接入前 `PetBehaviorId` 需扩枚举并补 EditMode 测试（各阈值边界线）。

### 4.2 技术硬约束（制作任何新动画前必读）

1. **不设计倒地、扑跳等需要骨盆/躯干大幅平移的动作**。已实测本项目的 FBX 烘焙管线承受不住非根骨骼平移（Foot/Pelvis 平移超过 1~2 mm，回读即偏离到 1.6e-2 m，WalkLoop 穿地问题同源）。例：红色系"暴怒"若是原地跺脚、鼓气、涨红一类即可；若设计成扑倒、翻滚则违反此约束，需改为 Unity 表现层整体位移替代并先过回读验证。
2. 新动画一律走：冻结骨架上加 Action → Blender 检查通过 → FBX 导出回读验证 → `HasAnimatorClip` 接线，才允许进状态机。
3. 表情变化（涨红、眯眼、撇嘴等）走 2D 表情贴图（Eyes/Oral 材质或叠加面片），不新增骨骼。
4. 专属动作的"专属感"优先用姿态与节奏做出来，少依赖幅度——幅度大会同时触发穿地与平滑度判据。

## 五、E4 汇报调研深化

现有《市场调研_AR萌宠产品横向对比》已覆盖 Peridot 停运、一起来捉妖停更、AR Dragon 停更与实体卡先例。最终汇报前补一轮专题检索（产出为报告章节或调研文档 v0.2）：

1. 宝可梦 GO 长线运营专题：AR 功能使用率、玩法重心从 AR 转向 LBS 的公开报道、远程 Raid 与外挂治理的历史节点。
2. AR 萌宠/AR 手游停运清单与归因：Peridot（2026-08-31 已停）、Harry Potter: Wizards Unite、Monster Hunter Now 等的运营数据与停运公告。
3. 结论落点：强化本项目"单机、本地存档、实体卡输入"定位的论证，回应"为什么不做联网对战与 LBS"。

## 六、实施顺序建议

1. **基线优先**：进食触发真机验证、跟踪丢失恢复回归、长时间双目标互动回归仍是主线，未完成前不启动新动画制作。
2. E1 材质变体（小成本，可与基线并行）。
3. E2 卡面美术与 Target Manager 验证（美术可与基线并行，入库接线放基线稳定后；卡面原画顺带产出动作 pose 参考）。
4. "动作与阈值定稿表"评审 → E1 专属动画逐段制作（最贵，最后）→ E3 逻辑接线与测试。
5. E4 调研检索放汇报前两周内完成。
