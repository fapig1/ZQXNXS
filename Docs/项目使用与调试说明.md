## 3. 运行时链路（排查时按这个顺序看）

`AppRoot.Update` 每帧固定顺序：

1. `PetSession.Tick`：每只宠物读自己卡的采样 → `TrackingStateMachine`（四态 + `CanInteract` / `CanShow`）→ 行为时钟（只在可交互时走）→ 表现层显隐。
2. 全局跟踪没在运行时取消所有按下与待判单击；单只丢失只取消它自己的。
3. `TickGestures`：到期的单击经 `InteractionPipe` 提交给 `PetSession.TrySubmit` → 该宠 `BehaviorStateMachine`（唯一结算点）。
4. `PetSession.TickSocial`：`ProximityRule` 判几何与停留 → `SocialCoordinator` 整组开始/取消。
5. `SaveCoordinator.Tick`：脏了才写，5 秒节流；切后台立即落盘。

显示与交互规则：

| 卡的跟踪状态 | 角色 | 能否点 / 结算 |
| --- | --- | --- |
| TRACKED 且位姿新鲜（<0.35s） | 显示 | 可以 |
| LIMITED 且位姿新鲜 | 显示（2026-10-27 修复：不再闪烁） | 不可以（碰撞体关闭） |
| EXTENDED_TRACKED / NO_POSE / 过期 / 暂停 | 隐藏（只关 Renderer/Collider，不 SetActive、不动 Observer） | 不可以 |

## 6. 常见问题排查

| 现象 | 先查 | 处理 |
| --- | --- | --- |
| 黑屏 / 没有相机画面 | 面板跟踪提示与 `[CameraPermission]` 日志 | 权限被拒后应用内不会再弹窗：到系统设置允许相机后切回应用，或重开应用 |
| 卡放好了角色不出现 | 面板列表该宠是否"寻找中"；`[PetSession]` 是否报目标卡未注册 | 卡要整张入镜、哑光、光线均匀；确认场景已用菜单 5/6 重建、`ZQXS.xml` 有四个 `card_*` |
| 角色出现但点不动 | 面板是否显示该宠"在场"；`[AppRoot] 交互 … → 拒绝` | LIMITED 时只显示不能点（卡太斜/太远）；动作执行中（Busy）点按会被拒绝、不排队；点在面板上不算 |
| 双击被当成两次单击 | 两次点按间隔 | 窗口 0.28s；手指移动超过 max(40px, 0.25 英寸) 或按住太久都不算合格点按 |
| 点满了不播专属 | 面板是否显示 "Full - tap to celebrate" | 读档时已满需再点一下确认；冷却中不会播；专属只开始一次，回落后要重新武装 |
| 两卡靠近不大笑 | 两卡是否都"在场"且可点；距离、高差、朝向 | 水平距离 ≤0.18m、高差 ≤0.035m、法向夹角 ≤20°、停留 0.6s；刚演完的一对贴着不动不会重演，要拿走一张卡 ≥2s 再换位（≥3cm）放回，或同时入镜拉开到 0.23m 外；logcat 过滤 `[ProximityRule]` 看该对是否锁着；任一只在忙会等，丢失会整组取消；每只有 5s 冷却 |
| 大笑中途停了 | `[SocialCoordinator] 会话 N 取消：原因` | 任一成员丢失或切后台整组取消，这是设计 |
| 表情不显示 / 原眼嘴露出 | `[PetPresenter]` 是否报缺格子或布局解析失败 | 重跑图集与 Blender 脚本后重建 02_Main；中性/Idle 时本来就显示原眼嘴 |
| 表情边缘锯齿、侧看有穿出 | `ArtSource/Characters/Pet01/Logs/FaceOverlay_20261027/visual_review_round8.md` | 已知残留（后续清单 L12）；rage 右 35° 远盘需外扩贴片网格 |
| 重启后进度回退 | `[SaveService] 写入失败` | Android 上不再调用 `File.Replace`，直接"备份 → 删除 → 移动"（第 10 节）；仍失败时取回存档目录查看 `.tmp` / `.corrupt_*` |
| 帧率低 | 面板右下角 FPS 与 CSV 的慢帧占比 | 目标 30FPS；记录设备温度与是否四卡同屏 |

## 9. 语音口令（2026-10-29）

**玩法**：按住屏幕底部"按住说话"，喊下表任一句，**所有在场**（卡在画面里且跟踪正常）的奶蛙用同一句录音回应。

| 口令 | 回应动作 | 表情 | 音效 |
| --- | --- | --- | --- |
| 安迪 | classic_proud（打招呼，2.0s） | 眯眼微笑 | 安迪 |
| 嘎嘎爹拉筛 | TouchReact（0.7s） | o 嘴 | 嘎嘎爹拉筛 |
| 雷霆大笑 | social_laugh 动作（2.4s，单只演，不算共同大笑会话） | 眯眼大笑 | 雷霆大笑 |
| 欧拉 | rage_roar（怒吼，2.0s） | 怒眼怒吼 | 欧拉 |

结算规则（`BehaviorStateMachine.TryAcceptVoice`，唯一结算点）：每只加分等同一次单击；同样走满值周期，跨越 100% 时改播该色专属演出（不播口令动作）；该宠 3 秒内只回应一次；正在做动作时拒绝、不排队；口令动作不在 `AnimatorStates` 里时拒绝。另：共同大笑开始时整组只播一次"雷霆大笑"，classic 专属播"安迪"，rage 专属播"欧拉"。

**链路**：`UI/VoiceHoldButton`（按住/松开）→ `Platform/VoiceKeywordListener`（麦克风采样、降到 16kHz、后台线程喂 `SherpaKeywordSpotter`）→ 命中原文进队列 → `AppRoot.Update` 的 `PumpVoice` → `AppRoot.SubmitVoicePhrase`（原文换口令 ID）→ `Interaction/VoiceCommandRule`（每只在场宠物一个 `InteractionEventKind.Voice` 事件，各自 Id 流）→ `InteractionPipe` → 各宠 `BehaviorStateMachine`。

**识别模型**：sherpa-onnx v2.0.1 离线关键词识别，模型 `sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01`（Apache-2.0），int8 encoder/joiner + fp32 decoder，约 5.4MB，放在 `ARPet/Assets/StreamingAssets/Voice/kws/`；首次启动解到 `persistentDataPath/kws/`。原生库：Android `Assets/Plugins/Android/sherpa-onnx/arm64-v8a/{libsherpa-onnx-c-api,libonnxruntime}.so`，编辑器 `Assets/Plugins/x86_64/sherpa-onnx/*.dll`。完全离线，不联网、不上传录音。

**离线验证（2026-10-29，Python sherpa-onnx 同版本同模型）**：

| 输入 | 结果 |
| --- | --- |
| Windows TTS（Huihui / Kangkang / Yaoyao）说四句口令 | 12/12 正确命中，无串词 |
| TTS 说"你好""今天天气不错""我们去吃饭吧"，3 秒白噪声，模型自带测试音频 | 0 误触发 |
| 开发者自录的四段表演配音 | 只有"安迪"命中；其余三段是夸张腔调的配音，不是正常说话，识别不出属预期 |
| Unity 编辑器加载真实原生库识别 TTS"雷霆大笑"/无关句/静音 | 命中 / 不触发 / 不触发（`VoiceAssetsTests.NativeSpotter_…`） |

**调参**：`VoiceKeywordListener` 的 `keywordsThreshold`（默认 0.25，越低越灵敏也越易误触发）、`keywordsScore`（默认 1.5，越高越易命中）、`maxListenSeconds`（默认 6）。冷却与加分在 `PetBehaviorConfig.asset`。

**改口令**：
1. 改 `PetBehaviorConfig.asset` 的 `VoiceCommands`（`Phrase` 是要说的中文，`CommandId`/`SfxId` 用英文）。
2. 改 `ARPet/Assets/StreamingAssets/Voice/kws/keywords_raw.txt`（每行 `短语 @短语`），然后 `pip install sherpa-onnx sentencepiece pypinyin` 并运行 `python Tools/Voice/make_keywords.py` 生成 `keywords.txt`。
3. 跑 Unity 测试：`VoiceAssetsTests.KeywordModel_IsComplete_AndCoversEveryCommand` 会检查关键词文件覆盖了全部口令。

**排查**：

| 现象 | 先查 | 处理 |
| --- | --- | --- |
| 按钮显示"语音识别库加载失败" / "缺少语音模型" | logcat `[VoiceKeywordListener]` | 确认 APK 里有 `lib/arm64-v8a/libsherpa-onnx-c-api.so` 与 `assets/Voice/kws/*` |
| 按钮显示"麦克风权限被拒绝" | 系统设置 → 应用权限 | 在系统设置中允许麦克风后回到应用，回前台时自动恢复，不用重启 |
| 按钮显示"没有可用的麦克风" | logcat `已有麦克风权限但没有找到麦克风设备` | 只在已授权但系统确实没给出设备时出现；再按一次按钮或切回前台会重新查找 |
| 喊了没反应 | logcat `[AppRoot] 语音“…”` 行 | "不是已知口令"=识别到别的；"没有在场的宠物"=卡不在画面里；没有这行=没识别出，按上面调阈值或说慢一点、离手机近一点 |
| 喊了只有部分奶蛙回应 | `[AppRoot] 交互 #N Voice[...] → 拒绝` | 那只正在做动作、3 秒冷却中，或跟踪是 LIMITED（只显示不可交互） |

## 8. 修改约束（改代码前看）

- 冻结模型 `ArtSource/Characters/Pet01/pet01.blend` 只读；不运行 `validate_pet01.py`；`promote` 前须归档并经用户同意。

- 存档以 schema 2 为准，按稳定 PetId 保存，不存场景引用或位姿。
- Active Input Handling 保持 Both，`TouchInputBridge` 用旧 Input API。
- 详细约束与当前状态以 [AGENTS.md](../AGENTS.md) 为准，残留事项见[后续修改问题清单](后续修改问题清单.md)。
